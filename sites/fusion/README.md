# Fusion Atlas — The paths to fusion power

A buildless editorial explainer at `/sites/fusion/`. Source lives in this repository. No API, CDN, database, external fonts, live news, or client framework. The first release is a reviewable local build; publication remains separate.

## Preview

From the repository root:

```sh
python3 -m http.server 4180 --bind 127.0.0.1
# http://127.0.0.1:4180/sites/fusion/
```

The full Jekyll host also works with `make serve` at http://localhost:4000/sites/fusion/.

If a Jekyll watcher is running, run production checks in an isolated destination so its development rebuild does not overwrite the production sitemap:

```sh
JEKYLL_ENV=production bundle exec ruby -E UTF-8 -S jekyll build --destination /tmp/fusion-atlas-production
python3 scripts/check-seo.py --site-dir /tmp/fusion-atlas-production
```

## Data and checks

`_handoff/` retains the supplied ZIP contents, including canonical JSON, build spec, dictionary, original validator and manifest. It is excluded from Jekyll output by its leading underscore. `fusion_atlas.json` is the byte-identical public canonical download. `data.json` is generated by `_extract.py`; it joins canonical claims, sites, sources and assessments for rendering, preserving native fields and intentional unknowns. Narrative fuel descriptions come from the accompanying report. Never edit the presentation data independently.

```sh
python3 sites/fusion/_extract.py
python3 sites/fusion/_validate.py
node sites/fusion/_test.mjs
node sites/fusion/_reactor-test.mjs
node sites/fusion/_assets.mjs
rsvg-convert sites/fusion/share-card.svg -o sites/fusion/share-card.png
JEKYLL_ENV=production bundle exec ruby -E UTF-8 -S jekyll build
make check-seo
```

The validator checks manifest integrity, canonical relationships and scientific/financial distinctions. Model tests exercise the supplied worked examples, per-shot Inertia accounting, negative output, zero capture/thermal efficiency, invalid driver efficiency, undefined ratios, URL bounds, target costs and all diagram states.

## Experience

- Six narrated reaction/plant stages, manual steps and opt-in playback.
- Fifteen explorable 3D machine families: orbit, zoom, camera presets, selectable components, focused inspection, assembly separation, isolation, layer controls, and opt-in animated energy paths. A component inspector explains each system, its engineering challenge, connected systems, and sources. Original four-stage SVG cycles remain available as expandable references.
- Company profiles include 39 relevant concept models with architecture-specific content and geometry where supported, including planar coil arrays, helical windings, patterned HTS surfaces, and separate fast ignition. Three enabling-infrastructure profiles use interactive system flows instead. Experimental machines omit future plant blankets and target supply systems.
- Four energy boundaries, experimental/target anchors, continuous and pulsed teaching models, and a separate attributed Inertia model. In Inertia mode, other demand is **MJ per shot**, multiplied by repetition rate.
- Selected published results with compatible metric views and original reported precision. No inferred success rate.
- Forty-two organizations, filters, evidence table, three-organization comparison, 83 site-role records and 71 financing observations. Shared sites are deduplicated; 3 locations remain intentionally unmapped.
- Six themes of engineering questions, full history, 167 searchable sources, ordinary source links and source detail dialogs.
- Deep links preserve approach, fast-ignition variant, filters, selected organization and comparison. “Copy scenario link” includes model inputs. Closing a detail dialog clears the entity query.

Default organization cards are the first nine in curated source order, with a control to expand all; this is not a ranking. Text and downloadable research remain available if JavaScript fails; interactive diagrams, filtering and the map require JavaScript. The map has a synchronized accessible list. No animation starts automatically; reduced-motion preferences disable smooth scrolling and any CSS motion.

## Editorial boundaries

Snapshot: **22 October 2026, America/Los_Angeles**. This implementation consumes the supplied research; it does not independently reproduce experiments or refresh the source claims. Observations, models, precursor results, organizational events and targets retain labels. Date precision and roles survive all evidence views. Currency, funding type, approximations, conditions and revisions survive the financing table; no sector aggregate is computed.

All diagrams and 3D models are original educational concepts, not device CAD or reconstructions, and are not to scale. Part positions and mechanical details are illustrative. Small targets are enlarged for inspection. SVGs are conceptual, not to scale. Timing is presentational. Company architectures with special constraints retain their profile explanation: planar-coil stellarators, Xcimer hybrid drive, First Light FLARE, laser fast ignition, and Fuse's test device versus proposed energy concept.

## 3D implementation

`reactor-explorer.js` is loaded on demand when a model enters the viewport. `reactor-geometry.js` provides disposable models, and `reactor-content.js` joins conceptual systems to the reviewed architecture/source records. No motion starts automatically. Rendering is event driven unless energy-path animation is explicitly enabled; animation pauses offscreen and in hidden tabs. Replaced models and closed dialogs release their WebGL resources. Keyboard orbit/zoom and ordinary component buttons provide alternatives to dragging. Browsers without WebGL retain a static schematic and component explanations.
